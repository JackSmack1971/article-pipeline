# Pitfall: article_spec.md claim-exclusion notes go stale after fact-check upgrades

**Trigger condition:** A claim is flagged for exclusion or de-attribution in `article_spec.md`'s
per-section "Key Claims" notes (written at spec-approval time, before FACTCHECK runs). The
fact-checker subsequently upgrades that same claim's verdict in `fact_check_report.md` /
`claims_for_drafting.md` (e.g., QUOTE-UNVERIFIED → VERIFIED-UPDATED). The spec is never
back-patched, so at drafting time the two artifacts give contradictory instructions for the
same claim ID.

**Observed instance:** ADV-10 ("GPT-5.3-Codex was instrumental in creating itself") was marked
"excluded/de-attributed per QUOTE-UNVERIFIED flag" in `article_spec.md`'s Section 6 Key Claims,
but `fact_check_report.md` located a primary source (OpenAI's own release page) and explicitly
upgraded it: "ADV-10 → upgraded, now usable." `claims_for_drafting.md` reflected the upgrade;
`article_spec.md` did not.

**Resolution used this run:** @engineer treated `claims_for_drafting.md` as authoritative per
the drafting protocol ("Read article_spec.md and claims_for_drafting.md (primary claim lookup)"),
included the claim as a paraphrase (no direct quotation marks, per the fact-checker's explicit
attribution instruction) with a source link, and documented the divergence and reasoning inline
in `audit_log.md` so the decision was traceable rather than silent.

**Recommendation for future runs:** Either (a) have FACTCHECK back-patch any `article_spec.md`
Key Claims note it supersedes, or (b) state explicitly in the DRAFT stage kickoff that
`claims_for_drafting.md` supersedes `article_spec.md` on any claim-handling conflict, so
@engineer doesn't have to re-derive this precedence rule from first principles each run.
